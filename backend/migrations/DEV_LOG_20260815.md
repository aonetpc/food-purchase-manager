## 二、核心错误与注意事项（必须牢记）

### ⚠️ 错误1：部署后体检项目数据被重复插入（201→230）

**根因**：
- `066_checkup_items_in_packages.sql` 含 `INSERT IGNORE INTO booking_checkup_items`（24条）
- `067_combo_items.sql` 含 `INSERT IGNORE INTO booking_checkup_items`（5条）
- deploy.yml 的 grep 正则只写了 `INSERT INTO`，漏掉了 `INSERT IGNORE INTO`
- 每次部署两个文件都被重新执行，插入 29 条重复数据

**修复**：
1. 重命名为 `066_checkup_items_in_packages_DONE.sql`
2. 重命名为 `067_combo_items_DONE.sql`
3. deploy.yml 正则：`INSERT INTO` → `INSERT.*INTO`

**经验教训（重要！）**：
> 📌 **迁移文件命名铁律**：含一次性 DML（INSERT/UPDATE/DELETE 用户业务表）的脚本，手动跑完后必须立刻改名为 `*_DONE.sql`。
>
> 📌 **grep 正则铁律**：检测 INSERT 必须用 `INSERT\s+(IGNORE\s+|LOW_PRIORITY\s+)?INTO`，不能只写 `INSERT INTO`。

### ⚠️ 错误2：新建套餐 SQL 语法错误 near '?,?'

**根因**：
- [checkup-templates.js#L295-L313](file:///workspace/backend/routes/checkup-templates.js#L295-L313) 的 INSERT columns 列表中包含了 `created_at`, `updated_at`（共14列）
- 但 args 数组只有 12 个值，缺少 `new Date()` 对应值
- MySQL 解析到末尾缺少参数 → 语法报错

**修复**：
- 从 columns 列表移除 `created_at`, `updated_at`
- 让 MySQL 的 `DEFAULT CURRENT_TIMESTAMP` 自动填充

**经验教训**：
> 📌 有 DEFAULT 值的列（created_at/updated_at/status/sort_order等）不要手动写入 INSERT，避免列数/参数数量不匹配。

### ⚠️ 错误3：Unknown column 'applicable_roles' in 'field list'

**根因**：
- 078 迁移脚本写法：`applicable_roles JSON NOT NULL DEFAULT '["male",...]'`
- **MySQL 5.7 不允许 JSON/TEXT/BLOB/GEOMETRY 类型列有 DEFAULT 值**
- 迁移执行到 ALTER TABLE 时报错，applicable_roles 列未被添加
- 但 schema_migrations 表已记录"已执行"→ 后续 deploy 跳过该文件

**修复**：
1. SSH 登录执行：`DELETE FROM schema_migrations WHERE id IN ('078', '080');`
2. 修改迁移脚本：先 `ADD COLUMN applicable_roles JSON NULL`（无DEFAULT）
3. 再 `UPDATE booking_packages SET applicable_roles = JSON_ARRAY(...) WHERE applicable_roles IS NULL;`

**经验教训（重要！）**：
> 📌 **MySQL 5.7 JSON 列铁律**：JSON 列绝对不能加 DEFAULT，必须分两步：
> ```sql
> ALTER TABLE t ADD COLUMN col JSON NULL;        -- 第1步：加列
> UPDATE t SET col = JSON_ARRAY(...) WHERE col IS NULL;  -- 第2步：填值
> ```
>
> 📌 **schema_migrations 陷阱**：migrate.js 只看迁移记录表，不看实际列是否存在。如果数据库被备份恢复，需手动清除迁移记录再重新执行。

### ⚠️ 错误4：Unknown column 'discount_rate' in 'field list'

**根因**：
- 078 迁移文件中 `discount_rate` 列只在 `booking_package_role_plans` 表定义
- 但代码 [checkup-templates.js#L297](file:///workspace/backend/routes/checkup-templates.js#L297) 中 INSERT booking_packages 时包含了 `discount_rate`
- 数据库中 booking_packages 缺少该列

**修复**：
```sql
ALTER TABLE booking_packages ADD COLUMN discount_rate DECIMAL(5,2) NOT NULL DEFAULT 100 COMMENT '折扣率%';
```

**经验教训**：
> 📌 改代码 INSERT 列时，必须先确认数据库表结构有对应列，或同步写迁移脚本。

## 四、正确操作流程速查

### 场景A：加一个一次性 DML 脚本（批量改分类/导入项目）
```
1. 写 081_xxx.sql（含 INSERT/UPDATE/DELETE）
2. git push → 自动部署（deploy.yml 会 grep 拦截并跳过 ✓）
3. SSH 登录服务器，手动执行：
   mysql -u food_purchase -p'xxx' food_purchase < migrations/081_xxx.sql
4. 立刻改名：
   mv 081_xxx.sql 081_xxx_DONE.sql
   git add -A && git commit -m "chore: rename 081 to _DONE" && git push
```

### 场景B：加列（schema DDL）
```
1. 写 082_xxx.sql（只含 ALTER TABLE ... ADD COLUMN）
   注意：JSON 列不能有 DEFAULT！
2. git push → 自动部署时 migrate.js 会执行
3. 验证列存在：DESCRIBE xxx;
4. 改名 _DONE.sql（可选，但建议）
```

### 场景C：数据库被备份恢复后，列缺失但迁移显示"已执行"
```
1. 查迁移记录：SELECT id, filename FROM schema_migrations WHERE id IN ('078','080');
2. 删记录：DELETE FROM schema_migrations WHERE id IN ('078','080');
3. 手动执行迁移：mysql < migrations/078_xxx.sql
4. 或直接手写 ALTER TABLE 补列
```

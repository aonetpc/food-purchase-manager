### 5. 追加项目支持默认选中 + 增减双向操作（P0）

- **需求**：原套餐包含的项目应在弹窗中显示为"默认选中"状态，用户可以取消选中来减少项目，实现增删闭环。
- **核心改造**：

  | 改动项 | 说明 |
  |--------|------|
  | 3 态模型 | 原套餐项目(绿色+`[套餐]`标签) / 新增选中(蓝色) / 已移除(红色删除线) |
  | `PickResult` 接口 | `{ addedIds: string[], removedIds: string[] }` — 确认时传递 diff 操作 |
  | 净变化金额 | `Σ(新增价格) - Σ(移除价格)`，正数绿色/负数红色 |
  | 分组统计 | 分类标题显示 `N 套餐 / +N 新增 / -N 移除` |
  | `removePaxItemById` | 按 `item_id` 精准移除单人定制项目 |
  | `removeSharedItemById` | 按 `item_id` 精准移除套餐共享项目 |
  | 重置按钮 | 一键清空所有变更（取消新增 + 恢复移除） |
  | Esc 键提示 | 有未确认变更时提示确认 |

- **数据流**：
  ```
  打开弹窗 → includedIds 初始化为 defaultSelectedIds（默认选中）
           → 点击原套餐项目 → 加入 removedIds（标记移除）
           → 点击未选项目 → 加入 userSelectedIds（新增选中）
           → 确认 → onConfirm({ addedIds, removedIds })
           → 父组件先执行 removedIds 移除，再执行 addedIds 新增
  ```

### 🟡 出错2：CapsuleItemPicker 浮层定位导致确认按钮不可见

📌 **错误过程**：
1. 初版用 `absolute` 定位 → 被 modal 的 `overflow-y-auto` 裁剪
2. 改用 `fixed` + `placeUp` 逻辑 → `max-h-[75vh]` 限制下底部确认条仍被挤出视口
3. `useLayoutEffect` 绑定 scroll/resize → 弹窗显示时内容滚动触发重新定位，造成抖动

📌 **教训**（弹层定位策略）：
1. **弹窗内的二级弹窗优先用居中 Modal**，不用跟随锚点定位
2. 居中 Modal + `max-h-[85vh]` + 底部 `shrink-0` = 确认条始终可见，无论内容多少
3. 只有在"需要保持上下文可见"的场景才用跟随定位（如 dropdown）

---

### 🟡 出错3：friendlyCapsuleName 识别逻辑脆弱

📌 **错误过程**：
1. 初版只识别 `套餐{8位hex}` 格式 → 其他格式直接返回原始 name（可能是 UUID）
2. `getPackageInfo` 回退链不完整 → 当 `capsuleMap[code]` 不匹配时直接返回 code 本身

📌 **修复后**：
1. 6 种丑陋格式识别：UUID、纯数字ID、`pkg_xxx`、`package_xxx`、无分隔长十六进制
2. 通过 `item_id` 相似度匹配已知套餐（score > 0.4）
3. 4 级回退链：capsuleMap → pkgMap → 名称反查 code → 硬编码常量

---

### 🟡 出错4：React Hooks 违规（error #310）

📌 **错误过程**：
1. 组合项目子项目弹窗中 `useMemo` 被放在条件分支内
2. 首次 render 走分支A（调了 useMemo），再次 render 走分支B（没调 useMemo）
3. React 检测到 Hooks 数量不一致 → error #310

📌 **教训**：
1. **所有 Hooks 必须在组件顶层无条件调用**，不能放在 if/else/循环内
2. 需要条件化的逻辑放在 Hooks 的回调函数内部，而不是 Hooks 调用本身

## 四、关键决策记录

### 决策 1：追加项目弹窗从"浮层定位"改为"居中 Modal"

- **选择**：废弃 `anchor` + `placeUp` 定位逻辑，改为 `flex items-center justify-center` 居中
- **原因**：
  1. 浮层定位在内容过多时底部确认条被裁切（核心 Bug）
  2. 居中 Modal 不受锚点位置影响，任何屏幕大小都可见
  3. 底部 `shrink-0` 确保确认条始终可见
  4. 用户体验更好（居中弹窗比偏移弹窗更符合直觉）

### 决策 2：追加项目从"仅增加"改为"增减双向"

- **选择**：原套餐项目默认选中（绿色+`[套餐]`标签），可点击标记移除（红色删除线），实现增删闭环
- **原因**：
  1. 用户的编辑需求不只有增加，还有减少项目
  2. 已包含项目灰色禁用不可选 → 用户无法取消不需要的项目
  3. 3 态模型直观展示当前状态：保留/新增/移除
  4. `PickResult` diff 接口让父组件精准执行增删操作

### 决策 3：体检意义数据用独立脚本而非迁移文件写入

- **选择**：编写 `update_clinical_significance.js` 独立脚本直连数据库批量更新
- **原因**：
  1. 迁移文件 `010` 语法错误阻断整条迁移链
  2. MySQL 5.7 的 `PREPARE/EXECUTE` 兼容性问题
  3. 迁移事务回滚导致数据写不进去
  4. 独立脚本不受迁移框架约束，直连数据库更可靠

### 决策 4：套餐名 6 种格式识别 + 智能匹配

- **选择**：`friendlyCapsuleName` 识别 UUID/纯数字ID/`pkg_xxx` 等 6 种格式，通过 `item_id` 相似度匹配已知套餐
- **原因**：
  1. 数据库中套餐名称格式不统一（UUID、纯ID、code 拼接等多种）
  2. 单一正则无法覆盖所有"丑陋"格式
  3. 通过 `item_id` 相似度匹配是最可靠的兜底方案（即使名称完全不可读，只要项目重叠度高就能匹配）

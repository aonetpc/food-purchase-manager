## 一、体检菜单权限缺失（fix/116 → 117 → 118 三连修）

### 1.1 现象

- 管理员 → 权限管理 → 编辑角色 → 权限配置弹窗里**没有「体检配单」「体检中心」**两个菜单项可配
- "食材采购管理"模块下多出一个**重复的"预订调度"**（脏数据）
- 侧边栏靠 `authStore.ts` 前端兜底注入才能看到这两个菜单（违反 Hard Constraints #17/#53）

### 1.2 根因

| 问题 | 根因 |
|---|---|
| 体检中心菜单从未注册 | migrations 里完全没有 `menu:checkup-center` 的 INSERT |
| 体检配单藏错模块 | 迁移 103 的 module_id 用 COALESCE 兜底成 `food-purchase`，藏到食材采购管理 |
| "预订调度"重复 | 063 迁移 module_id 兜底 food-purchase，064 只修 `code='menu:booking-board'` 的记录，碰不到 code 不同的脏数据 |
| authStore 兜底永久存在 | 之前没有迁移注册权限，前端兜底成了永久方案（违反 #17） |

### 1.3 fix/116 方案（首版，失败）

新建迁移 `107_fix_checkup_permissions_and_cleanup.sql`，6 动作：
1. INSERT IGNORE + UPDATE 补正 `menu:checkup-center`（module_id='booking-board'）
2. UPDATE `menu:checkup-templates` 的 module_id='booking-board'
3. DELETE `name='预订调度' AND code<>'menu:booking-board'` 脏数据
4. UPDATE `menu:booking-board` 的 module_id='booking-board'
5. 角色分配双保险：admin/booker 直接分 + 拥有 menu:permission 的角色自动补齐 3 个菜单
6. 验证查询

同时删 `authStore.ts` L281-311 三段兜底注入。

### 1.4 fix/116 部署失败原因

部署后权限配置没变化。用户执行 `migrate.js status` 发现 89 个迁移"待执行"——**migrate.js 的 `up` 从没成功跑过这些迁移**。

根因：`deploy.yml` L162 的 `node migrations/migrate.js up 2>&1 || echo "..."` —— `|| echo` 把迁移错误**静默吞掉**，第一个失败的迁移就让整个 up 终止，但部署继续走，导致 migrations 目录里大量迁移从未执行。

### 1.5 fix/117 方案（独立修复脚本绕过 migrate.js）

新建 `backend/scripts/fix-checkup-permissions.js`，直接用 mysql2 逐条执行 SQL，不走 migrate.js 的语句分割和 `|| echo` 吞错误链路。

脚本结构：步骤0修复前检查 → 步骤1-5执行修复 → 步骤6修复后验证。错误时打印 errno/code/sql 三要素。

`deploy.yml` migrate 阶段 recalc-package-role-plans 之后加一行调用此脚本。

### 1.6 fix/117 部署后部分生效

"预订调度"模块下出现了**体检中心** ✅，但**没有体检配单** ❌。

根因：fix/117 步骤2对 `menu:checkup-templates` **只有 UPDATE 没有 INSERT**。因为 103 迁移也没跑（89 个待执行之一），permissions 表里根本没有这条记录，UPDATE 影响 0 行。

### 1.7 fix/118 方案（加 INSERT IGNORE）

步骤2 和步骤4 统一为"INSERT IGNORE + UPDATE 补正"模式，和步骤1对 menu:checkup-center 一致。3 个菜单都走同一套幂等模式。

### 1.8 三连修教训

- migrate.js 的 `|| echo` 是系统性隐患，不能依赖自动迁移执行
- 独立数据修复脚本（mysql2 直连）比迁移更可靠，便于诊断
- **"只有 UPDATE"的幂等模式有漏洞**——记录不存在时 UPDATE 0 行等于没修，必须 INSERT IGNORE + UPDATE 双保险

## 二、体检克隆套餐"公共模板"标签 + code 超长（fix/119）

### 2.1 现象

预订员（ohh）克隆体检套餐时：
1. 生成的套餐显示"公共模板"标签（应该是个人套餐）
2. 基于衍生套餐再克隆时报 `Data too long for column 'code'`

### 2.2 根因

| 问题 | 根因 |
|---|---|
| 预订员被误判为管理员 | `isAdminOrManager` 的 adminPermCodes 里包含 `action:booking:config`，而 064 迁移给 booker 分配了 booking-board 全部权限（含此码），导致 booker 命中 isAdminOrManager → clone 时 is_public=1 |
| code 超长 | clone 接口 `code = srcPkg.code + '_' + 6位时间戳`，链式克隆：`PK12345678`(10) → `..._xxxxxx`(17) → `..._xxxxxx_xxxxxx`(24) > VARCHAR(20) |

### 2.3 修复方案

1. **isAdminOrManager 两处移除 `action:booking:config`**：业务常量配置权限不等于管理员权限，管理员判断只能基于真正的管理权限（权限管理/用户管理/角色管理/部门管理/企微管理）
2. **迁移 109 扩 code 到 VARCHAR(50)**：兜底保险
3. **clone code 改为固定 12 字符**：`'PK' + Date.now().slice(-8) + Math.floor(Math.random()*99)`，每代衍生都是 12 字符，永远不超长。追溯性通过 `base_template_id` 实现

### 2.4 衍生 N 代分析

| 代数 | 旧 code（叠加） | 长度 | VARCHAR(20) | 新 code（固定） |
|---|---|---|---|---|
| 1 代 | PK12345678 | 10 | ✅ | PK+8位+2位=12 |
| 2 代 | ..._xxxxxx | 17 | ✅ | 12 |
| 3 代 | ..._xxxxxx_xxxxxx | 24 | ❌ | 12 |
| N 代 | 每代 +7 字符 | ∞ | ❌ | 12 |

## 三、体检配单组合项目子项查看（feat/120 → 121 迭代）

### 3.1 需求

配单时组合项目（如肿瘤指标15项）默认看不到包含哪些子项，需要能查看详情。

### 3.2 feat/120 首版（卡片内独立按钮，失败）

在卡片底部加"查看N项详情 ▾"整宽按钮 + 展开竖排列表。

**失败原因**：卡片是 `min-h-[64px]` 紧凑布局，按钮被挤到卡片外或被 overflow 裁切，选中态绿底上按钮对比度低看不清。

### 3.3 feat/121 方案一（右上角 ⓘ 图标 + Modal，体验差）

右上角加蓝色 ⓘ 图标，点击弹出 createPortal Modal。

**体验问题**：ⓘ 和选中 ✓ / 公共 📌 挤在右上角，点击区域 p-1≈16px 太小，移动端难按。

### 3.4 feat/121 方案二（ⓘ 外挂卡片右侧，最终方案）

```
网格单元
┌──────────────────────────┐ ┌─┐
│ 🏥 肿瘤指标全套15项（罗） ✓│ │ⓘ│  ← ⓘ 外挂右侧，flex 布局
│  [组合·15项] [仅男性]     │ │ │
└──────────────────────────┘ └─┘
```

**关键设计**：
1. 外层包 `flex items-stretch gap-1` div 作为一个网格单元
2. 卡片 `flex-1 min-w-0`，ⓘ `w-6 shrink-0` 独立于卡片外
3. ⓘ 不和状态图标抢位，点击区域更大（全高 × 24px）
4. Modal 用 createPortal 到 body，不被父容器 overflow 裁切

**技术要点**：
- 卡片 `<button>` 改 `<div role="button">`（内部不能 button 套 button）
- Grid 布局里 ItemCard 不能返回 fragment（多元素会破坏网格），必须外层包一个 flex 容器

## 四、组合项目默认排前面（feat/122）

### 4.1 需求

配单时组合项目（肿瘤15项/甲状腺8项）默认排在单项前面，方便先选组合再补单项。

### 4.2 方案

`filteredItems` 两个 return 分支（公共 tab / 角色 tab）加 `.sort(sortComboFirst)`：

```typescript
const sortComboFirst = (a, b) => {
  if (a.item_type === 'combo' && b.item_type !== 'combo') return -1;
  if (a.item_type !== 'combo' && b.item_type === 'combo') return 1;
  return 0; // 组内保持后端原顺序（现代浏览器 sort 稳定）
};
```

**优点**：纯前端 +9/-2 行，零后端改动，组内顺序不变。

## 七、新增约束（写入项目记忆）

1. **数据修复优先用独立脚本而非迁移**：当 migrate.js 有 `|| echo` 吞错误等系统性问题时，新建 `backend/scripts/fix-xxx.js` 用 mysql2 直连执行，deploy.yml 里调用，错误可诊断可重跑
2. **幂等修复必须 INSERT IGNORE + UPDATE 双保险**：不能只有 UPDATE（记录不存在时 0 行等于没修），也不能只有 INSERT（已存在时不改字段）
3. **isAdminOrManager/adminPermCodes 只能包含真正的管理权限**（menu:permission/users/roles/departments/wecom），不能包含 action:booking:config 等业务权限，否则业务角色会被误判为管理员
4. **code 等唯一标识字段禁止叠加式生成**（srcPkg.code + 后缀），链式操作会超长；应固定长度生成，追溯性通过外键字段实现
5. **Grid 子组件必须返回单一根元素**：如果组件内部需要多个并排元素（如卡片+外挂按钮），外层包 flex 容器作为一个网格单元，不能返回 fragment
6. **前端排序用 .sort() 不破坏 filter**：现代浏览器 sort 稳定，只需在 filter 结果后加 .sort()，组内顺序不变

## 二、出错的地方（重点记录）

### 🔴 出错1：TDZ 临时死区错误（Cannot access variable before initialization）

📌 **错误过程**：
1. 体检预订界面改造时，`roleBasedTotal` 的 `useMemo` 在 `drawerAmount` 的 `useMemo` 之后声明
2. 但 `drawerAmount` 内部引用了 `roleBasedTotal` → 此时 `roleBasedTotal` 尚未初始化
3. React 运行时报 `Cannot access 'roleBasedTotal' before initialization`（TDZ）

📌 **修复**：调整变量声明顺序，将 `roleBasedTotal` 等变量移至 `drawerAmount` 之前，并补全依赖数组。

📌 **教训**：
1. **`useMemo` 之间的依赖关系决定了声明顺序**：如果 B 依赖 A，A 必须在 B 之前声明
2. **TDZ 是运行时错误不是编译错误**：TypeScript 检查不出，只有运行时才报
3. **改完后必须实际点击 UI 验证**：尤其是涉及 `useMemo` 依赖链的改动

---

### 🔴 出错2：婚姻状态字符串 vs 布尔值判断错误

📌 **错误过程**：
1. 已导入统计中用 `p.married === '已婚'` 判断已婚
2. 但实际 `married` 字段是布尔值 `true/false`，不是字符串
3. 导致已婚女统计为 0，未婚女统计翻倍

📌 **修复**：`if (p.married)` 布尔值判断。

📌 **教训**：
1. **后端字段类型必须确认是布尔还是字符串**：不能凭字段名猜类型
2. **统计类逻辑必须有数据验证步骤**：改完后用真实数据验证一遍

---

### 🔴 出错3：保存金额计算口径不一致 + 编辑模式状态丢失

📌 **错误过程**：
1. 保存时金额仅按导入名单求和，未使用角色设定人数 → 金额不对
2. 编辑时未恢复 `selectedChkPkg` 和 `roleCounts` 状态 → 看不到之前选的套餐和人数

📌 **修复**：
1. 优先使用角色设定人数计算金额
2. 保存时将 `selectedChkPkg` 和 `roleCounts` 存入 `extra`
3. 编辑时从 `extra` 恢复状态

📌 **教训**：
1. **新增的 state 如果需要在编辑时恢复，必须持久化到 `extra` 或后端字段**
2. **金额计算逻辑要统一口径**：不能保存时用一种算法、展示时用另一种

---

### 🟡 出错4：getConfig 字段名 camelCase/snake_case 不匹配

📌 **错误过程**：
1. `fromBackend` 统一把 snake_case 转 camelCase
2. 但 `getConfig()` 中各字段直接用 camelCase 读取后端返回的 snake_case → 读不到
3. 导致 `mealTypes`/`roomTypes` 等全为空，用 fallback 硬编码

📌 **修复**：对各字段采用双读兜底：`d.mealTypes || d.meal_types || []`。

📌 **教训**：
1. **`fromBackend` 不是万能的**：批量 map 转换后，嵌套数组内的字段可能仍是 snake_case
2. **配置类接口必须双读兜底**：`camelCase || snake_case || fallback`

---

### 🟡 出错5：套餐定价保存时唯一索引冲突

📌 **错误过程**：
1. 角色级排除功能保存时，将排除的公共项目拆为未排除角色的专属项目
2. 如果同一项目已存在该角色的记录 → 唯一索引冲突报错

📌 **修复**：后端启动时自动修复索引 + 简化 migration SQL 语法（PREPARE 兼容性）+ 保存逻辑先删后插。

📌 **教训**：
1. **新增角色专属项目时要先查重**：不能直接 INSERT
2. **MySQL 5.7 的 PREPARE/EXECUTE 在迁移脚本中不稳定**：尽量用简单 SQL

---

### 🟡 出错6：JSX 在模板字符串中不被解析

📌 **错误过程**：
1. 住宿明细的单晚价格区域用 `<>...</>` Fragment 嵌在模板字符串三元表达式内
2. 康乐明细的住客标签用 `'<span>...</span>'` 字符串写在 JSX 表达式里
3. 两者都不会被 React 解析为 DOM 元素

📌 **修复**：改为正常的 JSX 三元表达式，不混用模板字符串和 Fragment。

📌 **教训**：
1. **JSX 区域内不能混用模板字符串和 Fragment 语法**
2. **`'<span>'` 字符串不会渲染为 HTML**：必须写 `{cond && <span>...</span>}`

## 四、关键决策记录

### 决策 1：体检展开瘦身——删除人头项目明细表

- **选择**：只保留三角色摘要 + 名单导出 + 套餐查看/导出，删除 400+ 行的人头明细
- **原因**：20人×20项=400行在弹窗内不现实；名单和套餐通过 xlsx 导出分流到外部使用

### 决策 2：名单导出不脱敏

- **选择**：身份证和手机号完整导出，不加脱敏开关
- **原因**：前台要导入体检系统，脱敏后无法导入

### 决策 3：套餐查看不用 PDF，用 Excel

- **选择**：内嵌 Sub-Modal 查看三角色项目 + Excel 3 sheet 导出
- **原因**：需要导入到体检系统，PDF 不支持导入

### 决策 4：所有业务行统一可展开 + 弹窗同尺寸

- **选择**：8 种业务行全部加箭头+hover+点击展开，不用独立 Modal 叠层
- **原因**：同弹窗内展开 = 尺寸天然统一；独立 Modal 叠层 z-index/遮罩/Esc 管理复杂

### 决策 5：按角色人数计算体检合计（不按名单）

- **选择**：`合计 = Σ(角色设定人数 × 角色单价)`，与上传名单数无关
- **原因**：预订时确定来多少人，名单可能拿不到

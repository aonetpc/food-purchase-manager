## 二、fix/095 Out of sort memory 终极修复详情

### 2.1 事故时间线

| 时间 | 事件 |
|------|------|
| 8-31 12:05 | 第一版 deferred join（`4a07c6d`）→ 仍 filesort booking_items.extra |
| 8-31 12:29 | 签字 200KB 硬限制（`7dade33`）→ 防止新增大签字 |
| 9-1 09:33 | TEMPORARY TABLE + STRAIGHT_JOIN（`bb8f42b`）→ 阶段1只插 id 到 temp table |
| 9-1 09:33 | merge（`4e725c6`）→ 部署后发现 /orders/search 仍用旧逻辑 |
| 9-1 10:08 | fetchBookingItemsSafely 2-phase（`d238fee`）→ 阶段1只选 id，阶段2 WHERE IN 取全列，但仍有 `ORDER BY FIELD(id,...)` |
| 9-1 ~12:00 | **发现根因**：阶段2 `ORDER BY FIELD(id,...)` 仍把 extra 宽列拉入 sort_buffer → **去掉 SQL ORDER BY，改 JS Map 重组**（`d8a2b0e`） |
| 9-1 ~12:03 | 部署 + 两轮冒烟（NULL → 恢复 667KB extra）→ 0 次 Out of sort ✅ |

### 2.2 最终方案（fetchBookingItemsSafely）

```javascript
// 阶段1：只查窄列 id（VARCHAR(36)），filesort 永不爆
const [idRows] = await pool.query(
  `SELECT id FROM booking_items WHERE order_id IN (?) ORDER BY sort_order, id`,
  [orderIds]
);
const ids = idRows.map(r => r.id);

// 阶段2：WHERE IN 取全列，SQL 不带任何 ORDER BY
const [rows] = await pool.query(
  `SELECT * FROM booking_items WHERE id IN (?)`,
  [ids]
);

// 阶段3：JS 应用层用 Map 按 ids 序还原顺序
const rowMap = new Map(rows.map(r => [r.id, r]));
return ids.map(id => rowMap.get(id)).filter(Boolean);
```

### 2.3 关键教训

| 教训 | 说明 |
|------|------|
| `ORDER BY FIELD(id, ...)` 也是 ORDER BY | 即使只排 id 列，MySQL 仍会把 SELECT * 的全列拉入 sort_buffer 算行宽 |
| 两阶段查询必须彻底去掉 SQL ORDER BY | 阶段2的排序只能在 JS 层做，SQL 里一个 ORDER BY 都不能有 |
| 冒烟测试必须两轮 | ① 宽列为 NULL → ② 恢复最大 extra → 都不报 Out of sort 才算闭环 |

## 八、踩坑教训（续 #42，新增 #43~#47）

| # | 踩坑 | 教训 |
|---|------|------|
| 43 | **`ORDER BY FIELD(id, ...)` 仍触发 filesort 全宽列**：即使 FIELD 函数只排 id 列，MySQL 优化器仍按 SELECT * 的行宽计算 sort_buffer 需求 | 两阶段查询的阶段2 **SQL 里不能有任何 ORDER BY**，排序只能在 JS 层用 Map 重组 |
| 44 | **appleboy/ssh-action PTY 模式注入 ANSI 颜色码 + CRLF**：`systemctl list-unit-files` 输出被污染，`grep '^xxx.service'` 行首锚定失效，明明存在的服务匹配不到 | SSH Actions 条件判断**只看退出码**：`systemctl cat xxx.service >/dev/null 2>&1` 看返回 0/非0；端口存活用 `curl -sf`；不要解析 stdout 文本 |
| 45 | **路由裸奔 = RBAC 形同虚设**：即使后端 RBAC 权限数据正确，前端路由如果没有 ProtectedRoute 包装，用户直接输入 URL 就能访问页面 | 所有业务路由必须加 ProtectedRoute 守卫，不能只靠侧边栏菜单隐藏 |
| 46 | **默认首页硬编码 → 所有角色看到同一个页面**：`<Navigate to="/daily">` 让所有人登录后都跳采购清单 | 默认首页必须动态化：基于 getUserMenus() 取用户第一个有权限的 PC 菜单 |
| 47 | **Page Visibility API 做 30min 自动刷新**：tab 不可见时暂停刷新，可见时恢复，避免后台无效请求 | 使用 `document.visibilityState === 'visible'` + setInterval，visibilitychange 事件控制暂停/恢复 |

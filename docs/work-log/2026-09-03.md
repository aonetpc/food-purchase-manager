## 一、背景 & 需求

### 1.1 用户原始场景

销售员在接待客户时会遇到：
- 客户对体检套餐感兴趣，但**还没最终确认具体套餐**
- 但**预估金额**已经和客户谈好（客户已给预算范围）
- 需要**先下单占位**，防止同一天被其他销售员预订超量
- 等客户确认后，**再补选胶囊+名单**，然后走「销售员确认」流程

### 1.2 现有系统的阻塞点（9-2 下午排查确认）

体检抽屉里有一条**强制依赖链**，不选套餐胶囊就无法输入人数和价格：

```
选销售员 ──useEffect──► 加载该销售员专属 salesCapsules 胶囊列表
                          │
                          ▼
                    点选胶囊 setSelectedChkPkg(cap.id)
                          │
                          ▼
              {selectedChkPkg && (...)}  ← JSX 门控，没选胶囊不渲染人数输入框
                          │
                          ▼
              每角色价格 = getCapsulePriceByRole(selectedChkPkg, role)
              ↑ 只读，前端无法修改
                          │
                          ▼
              roleBasedTotal = Σ(人数 × 胶囊折后价)
```

**三个卡死点**：① 不选胶囊不显示人数输入 ② 价格从胶囊读取无法手输 ③ 不选胶囊 roleBasedTotal 永远为 0。

### 1.3 用户排除项（9-2 对话澄清）

用户明确说"并不是方案里这些优化内容"，所以排除：
- ❌ 草稿按钮文案调整
- ❌ 销售员视角项目库搜索
- ❌ "待补名单"角标（画板普通 pending 卡上的）
- ❌ 放宽保存校验（允许 0 item）

**用户要的是**：不选胶囊也能**手输三角色单价 × 人数**自动算金额，先占位。

## 六、业务流程走通性分析（未测试，代码路径推断）

### 6.1 占位下单（预测单 pending）

```
1. 销售员点「+」或拖格子新建 → 选客户名+销售员
2. 加体检项 → 抽屉顶部切「✍️ 自定义占位」
   ├─ 琥珀色提示：⚠ 套餐未确认占位…
   ├─ 占位备注：输入"客户待确认套餐"（可选）
   ├─ 男性：单价 ¥3500，[3 人]
   ├─ 已婚女：单价 ¥3800，[2 人]
   └─ 未婚女：单价 0，[0 人]
   → 底部实时金额：3×3500 + 2×3800 = 18100
3. 点「保存草稿」
   ├─ saveDrawer → checkupMode='placeholder' 分支
   ├─ 校验通过（rolePaxTotal=5，有角色单价×人数>0）
   ├─ item.extra = { paxList:[], roleCounts:{m:3,fm:2,fs:0}, customPrices:{m:3500,fm:3800,fs:0}, isPlaceholder:true, placeholderNote:"客户待确认套餐" }
   └─ order.status = 'pending'（预测单，黄色）
4. 画板显示
   ├─ 黄色预测单卡 + 右上角 amber「占位」角标
   └─ 显示「5人 · ¥18,100」
```

### 6.2 补套餐（切选胶囊模式）

```
1. 点占位卡 → 编辑 → 体检抽屉自动识别 isPlaceholder=true → 切到占位 Tab
2. 销售员手动切到「📋 选择套餐」→ 胶囊列表出现
3. 选一个胶囊（例：标准A）
   ├─ checkupMode 从 'placeholder' → 'package'
   ├─ roleCounts 保留（{m:3,fm:2,fs:0}，不用重输）
   ├─ 单价自动变成胶囊标准A对应价（男¥3800, 已婚女¥4200…）
   └─ 底部金额自动重算：3×3800 + 2×4200 = 19800
4. 点保存 → saveDrawer 走 package 分支 → isPlaceholder=false
5. 画板显示
   ├─ 「占位」角标消失
   └─ 金额更新为胶囊价
6. 可选：导入名单 + 点画板「提交确认」→ pending → sales_confirming → 审核流程
```

- ⚠️ 切 Tab 时 `isPlaceholder` 的清除是否正确（package 分支在 saveDrawer L2486 显式设 `isPlaceholder:false`，有兜底）

## 八、约束性内容（拟写入项目记忆）

以下条目从本次工作推导，属于"下次做 Booking 模块扩展时不用重新想"的硬约束和经验：

1. **Booking 体检扩展字段优先塞 extra JSON 列**：只要该字段不需要在 SQL 里 WHERE/JOIN/GROUP BY，一律扩展 `booking_items.extra`（ItemExtra 类型），后端和数据库 0 改动。已验证可行的 pattern：selectedChkPkgId、roleCounts、paxListCount、customPrices、placeholderNote、isPlaceholder。
2. **体检"选胶囊 vs 手输"互斥**：不能同时有 selectedChkPkg（胶囊价）和 customPrices（手输价），用 `checkupMode: 'package' \| 'placeholder'` 显式分模式，金额计算和保存逻辑各自走分支，避免 UI 同框两个价格互相覆盖。
3. **isPlaceholder 是画板角标/确认页 UI 判断的通用标记**：任何"占位/预估/待确认"的体检项，统一用 `item.extra.isPlaceholder === true` 判定，不要用其他 heuristic（如 `paxList.length===0` 可能是销售员没填完真实名单也空着，会假阳性）。
4. **占位模式的保存校验 2 条硬线**：(a) 人数>0（不能 0 人下单）；(b) 至少有一个「单价>0 × 人数>0」的角色组合（防止算出来金额 0 却能占位）。
5. **从占位→真实套餐的升级路径必须是"切 Tab + 选胶囊"，一键升级**：roleCounts 保留不丢，用户只需要点一个胶囊，价格自动替换成胶囊价重新算 total，不重输人数。
6. **自检组合拳**：`npm run build`（通关标准）+ `npm run check` 过滤改动文件（排查我引入的类型错误）+ `git diff --stat`（确认改动文件范围）+ Grep 红线文件名（防误触禁止修改的文件）。4 步 10 分钟跑完。

## 一、fix/160：库存盘点多角色权限修复

### 1.1 背景

用户 li 增加「出纳」(cashier) 角色后，库存管理页面的盘点 Tab 消失。而只有「财务」(finance) 单角色的用户 min 能正常显示。

### 1.2 根因

三层链路叠加：

| 层 | 位置 | 问题 |
|----|------|------|
| 1. 登录查角色码 | `auth.js` `getUserRoleCodes()` L108-119 | SQL **没有 `ORDER BY r.sort_order ASC`**，多角色返回顺序不确定 |
| 2. 取主角色 | `auth.js` L179-180 | `roleCodes[0]` 可能取到 `cashier`(sort_order=15) 而非 `finance`(sort_order=2) |
| 3. 前端判断 | `InventoryManager/index.tsx` L35 | `MANAGER_ROLES.includes(user.role)` → `'cashier'` 不在列表 → `isManager=false` → 盘点 Tab 隐藏 |

对比：后端 `rbac.js` `requireAuth` 中间件 (L73-83) 有 `ORDER BY r.sort_order ASC LIMIT 1`，正确取到 `finance`。**auth.js 和 rbac.js 取主角色的 SQL 不一致**是根因。

### 1.3 改动（3 files，6增5删）

**后端** `backend/routes/auth.js`：
- `getUserRoleCodes()` SQL 加 `ORDER BY r.sort_order ASC`
- 确保 `roleCodes[0]` 取 sort_order 最小的角色，与 `rbac.js` `requireAuth` 一致
- 3 个调用点自动受益：login / wecom-login / bind-wecom

**前端** `src/pages/InventoryManager/index.tsx`：
- `MANAGER_ROLES.includes(user.role)` → `hasRole(['admin', 'finance', 'boss'])`
- 从 `useAuthStore()` 获取 `hasRole` 函数

**前端** `src/pages/InventoryManager/StockTakePanel.tsx`：
- `MANAGER_ROLES.includes(user.role)` → `hasRole(['admin', 'finance', 'boss'])`
- `CAN_REVIEW_ROLES.includes(user.role)` → `hasRole(['admin', 'finance'])`
- 2 处均复用 `authStore.hasRole()` 的多角色归一化逻辑

### 1.4 踩坑

## 二、fix/161：会签节点导致列表重复 — SQL JOIN 改子查询聚合

### 2.1 背景

审批单 `sp_no=202409100001` 在费用支付监控页出现 2 行重复。

### 2.2 根因

节点 2 是会签节点（需两人确认），`wecom_expense_approval_nodes` 表同一 `sp_no` 同一 `node_index` 有 2 行 `is_current=1` 记录（每个审批人各一行）。直接 `LEFT JOIN` 导致主表 1 行 × 节点表 2 行 = 笛卡尔积，列表出现重复行。

### 2.3 改动（1 file，19增2删）

**后端** `backend/routes/expense-approvals.js`：
- 监控页列表 `GET /` (L475) 和我的报销页列表 `GET /my` (L578) 的 JOIN 改为子查询聚合：

```sql
LEFT JOIN (
  SELECT sp_no,
         MAX(node_name) AS node_name,
         GROUP_CONCAT(approver_name SEPARATOR '、') AS approver_name
  FROM wecom_expense_approval_nodes
  WHERE is_current = 1
  GROUP BY sp_no
) cn ON e.sp_no = cn.sp_no
```

- 子查询先按 `sp_no` 聚合为一行，避免主表行重复
- 审批人用 `GROUP_CONCAT` 合并为"张三、李四"格式，会签场景更直观
- 详情页 `GET /:sp_no` 保持不变，仍查节点表所有行展示完整审批链路

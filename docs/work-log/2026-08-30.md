## 二、fix/094 权限修复详情

### 2.1 问题背景

用户 `aonetpc`（钱育健）在操作体检套餐分配（`PUT /api/booking/checkup-templates/:id/cover-sales`）时收到 403「仅管理员可分配套餐」，但该用户右上角显示「管理员」角色。

### 2.2 根因分析

| 层级 | 代码位置 | 问题 |
|------|---------|------|
| `requireAuth` | `rbac.js` | 正确挂载了 `req.user.permissions` 和 `permissionCodes`(Set)，多角色合并 |
| `isAdminOrManager` | `checkup-templates.js L131-134` | **只看 `user.role` 单字符串主角色**，无后续兜底 |
| `requireAuth` 主角色选取 | `rbac.js` | `ORDER BY sort_order ASC LIMIT 1`，双角色用户的主角色可能不是 admin |
| 前端 `authStore.isAdmin()` | `authStore.ts L160-166` | 正确检查 `user.roles[]` 数组 → 前后端不一致 |

### 2.3 修复方案（方案 A，用户确认后执行）

将 `isAdminOrManager(user)` 从同步函数重写为 **async 三级兜底**：

1. **主角色命中**：`user.role` ∈ {admin, boss, manager}
2. **多角色表兜底**：`user_roles UNION users.role_id` 查询所有角色 code，命中 admin/boss/manager
3. **权限码降级**：`permissionCodes` Set 包含任一管理级权限码（menu:permission / menu:users / menu:roles / menu:departments / menu:wecom / action:booking:config）

同时将 `canUserViewPackage` / `canUserEditPackage` 改为 async，内部 `await isAdminOrManager(user)`。

## 六、经验教训（今日新增 #28~#31，接上篇 #19~#27）

| # | 踩坑点 | 教训 |
|---|--------|------|
| 28 | **自定义权限函数只查单角色 → 双角色用户被 403**：`isAdminOrManager(user)` 同步函数仅看 `user.role` 单字符串，双角色用户（admin+sales）主角色可能是 sales → 被错误拦截。而前端 `authStore.isAdmin()` 正确检查 `user.roles[]` 数组，导致"右上角显示管理员但后端拒绝"的困惑 | 自定义权限函数必须与 RBAC 中间件三级兜底对齐：①主角色 → ②多角色表 UNION → ③权限码降级 |
| 29 | **同步→async 改造遗漏调用点**：`isAdminOrManager` 从同步改 async 后，14 处调用点都需要加 await。遗漏的同步调用会返回 Promise 对象（truthy），导致权限判断永远通过或永远失败 | 改造后必须用 Grep 全局搜索函数名，逐一确认所有调用点都加了 await |
| 30 | **分享页多层 `../../` 相对路径 import 不存在**：`../../api`、`../../components/ToastMessage`、`APPOINTMENT_ROUTES` 路径在文件移动后断裂 | 统一使用 `@/` 别名或同级 `./` 相对路径，禁止 3 层以上 `../../` |
| 31 | **PDF 渲染逻辑不要为分享页单独写一套**：分享页 PDF 应复用内部 renderPdfItemsSection helper，通过参数控制去价格列 | 复用优于重写，减少维护成本和分页不一致风险 |

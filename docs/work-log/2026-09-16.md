## 一、fix/176：月结付款附件自动发现 File 控件

### 1.1 背景

用户反映：发起月结付款时上传了发票作为附件，但企微审批单内没有正常上传到附件字段。用户指出附件上传代码应该和仓库采购的预付采购相同。

### 1.2 根因定位

**对比代码发现两处附件填充逻辑差异**：

- **仓库采购** [warehouse-purchases.js L694](file:///f:/OA/backend/routes/warehouse-purchases.js#L694) ✅ 工作正常：
  ```js
  const fileControlId = fieldMapping.attachment
    || Object.entries(controlTypeMap).find(([, ctype]) => ctype === 'File')?.[0];
  ```
  有**自动发现 File 控件**兜底：`fieldMapping.attachment` 未配置时，从 `controlTypeMap` 找类型为 `File` 的控件作为兜底。

- **对账中心** [reconciliation.js L717-723](file:///f:/OA/backend/routes/reconciliation.js#L717) ❌ 修复前：
  ```js
  if (fieldMapping.attachment && uploadedAttachments.length > 0) {
    contents.push({ ..., id: fieldMapping.attachment, ... });
  }
  ```
  **只用 `fieldMapping.attachment`**，没配置就跳过附件填充。

附件其实已上传成功（[L619-636](file:///f:/OA/backend/routes/reconciliation.js#L619) base64 解码 + `uploadMedia` 上传逻辑与仓库采购 L3533-3549 完全一致，已拿到 `mediaId`），但 `fieldMapping.attachment` 在企微配置页没映射到模板里的 File 控件 id，导致附件被丢弃。

### 1.3 改动（1 file，+6/-3）

**[reconciliation.js L717-727](file:///f:/OA/backend/routes/reconciliation.js#L717)** 附件填充加自动发现兜底：

```js
// 附件（参照 warehouse-purchases.js buildWarehouseApplyData 的自动发现逻辑）
// fieldMapping.attachment 未配置时，从 controlTypeMap 自动发现 File 类型控件作为兜底
const fileControlId = fieldMapping.attachment
  || Object.entries(controlTypeMap).find(([, ctype]) => ctype === 'File')?.[0];
if (fileControlId && uploadedAttachments.length > 0) {
  contents.push({
    control: getControlType('attachment', 'File'),
    id: fileControlId,
    value: { files: uploadedAttachments.map(a => ({ file_id: a.mediaId })) },
  });
}
```

完全复用 [warehouse-purchases.js L694](file:///f:/OA/backend/routes/warehouse-purchases.js#L694) 的实现。

### 1.4 验证点

- ✅ 审批单里出现附件字段，显示已上传的发票
- ✅ 即使企微配置页没映射 attachment 字段也能填充（自动发现兜底）
- ✅ 无附件场景不会填充空 File 控件（`uploadedAttachments.length > 0` 条件保留）

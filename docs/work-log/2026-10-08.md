# 2026-10-08 工作复盘

> 涉及分支：`fix/203-booking-flow-log-user-undefined`
> 主题：修复预订订单提交/保存时报 `user is not defined` 且企微通知丢失
> 状态：分支已提交，待安全检查通过后合并 main 部署

---

## 一、问题背景

用户「ohh」反馈预订调度看板 3 个异常：

1. **新建订单后点击「提交确认」报错**：`提交失败: user is not defined`
2. **修改订单后保存报错**：`保存失败: user is not defined`
3. **刷新页面后订单显示「审核中」，但企微群里没收到确认通知**，对应的销售员企微也没收到确认 H5 页面消息

用户补充：「之前没有问题，应该是前面修改角色权限问题之后出现的」。

---

## 二、根因分析

### 2.1 直接原因

`feat/196-booking-flow-logs`（审批流程历史记录功能）在 7 个订单流转操作接口中追加了 `writeFlowLog(conn/pool, orderId, action, actionLabel, user, extra)` 调用。

但其中 **3 个 handler 忘记声明 `const user = req.user || {};`**，导致 `writeFlowLog` 调用时引用了未定义的 `user` 变量，抛出 `ReferenceError: user is not defined`。

### 2.2 受影响的接口

| 接口 | 路由 | `const user` 是否声明 |
|------|------|----------------------|
| 新建 | POST `/orders` | ✅ 有 |
| 复制 | POST `/orders/:id/duplicate` | ✅ 有 |
| **提交确认** | **POST `/orders/:id/submit`** | ❌ **缺失** |
| 销售确认 | POST `/orders/:id/sales-confirm` | ✅ 有 |
| **撤回** | **POST `/orders/:id/withdraw`** | ❌ **缺失** |
| 审核通过 | POST `/orders/:id/approve` | ✅ 有 |
| 驳回 | POST `/orders/:id/reject` | ✅ 有 |
| 标记完成 | POST `/orders/:id/complete` | ✅ 有 |
| **编辑保存** | **PUT `/orders/:id`** | ❌ **缺失** |

### 2.3 三个症状的因果链

**症状 1（提交失败）**：
```
L1958: UPDATE status = 'sales_confirming'   ← 先执行成功，状态已改
L1971: writeFlowLog(..., user, {})           ← 引用未声明 user → 抛 ReferenceError
L1995: sendBookingNotification('submit')     ← 永远到不了，通知没发
catch → res 500                              ← 前端显示「提交失败: user is not defined」
```

**症状 2（保存失败）**：
```
L2613: conn.commit()                         ← 先执行成功，数据已存
L2616: writeFlowLog(..., user, ...)          ← 引用未声明 user → 抛 ReferenceError
L2620: handleOrderEditNotification(...)      ← 永远到不了
catch → res 500                              ← 前端显示「保存失败: user is not defined」
```

**症状 3（状态变了但没通知）**：
- submit 接口的 `UPDATE status='sales_confirming'` 在报错前已执行
- 刷新页面后订单确实变为「待确认」
- 但 `sendBookingNotification` 因 `writeFlowLog` 报错被跳过
- → 企微群和销售员都没收到通知

### 2.4 为什么「之前没问题」

flow logs 功能部署前，这 3 个 handler 根本不调用 `writeFlowLog`，自然不会引用 `user` 变量。部署后第一次执行 submit/edit 就触发了 `ReferenceError`。

---

## 三、修复方案

在 3 个 handler 的 `writeFlowLog` 调用之前，补上 `const user = req.user || {};`，与另外 4 个 handler（sales_confirm / approve / reject / complete）保持一致。

| 位置 | 插入行 | 内容 |
|------|--------|------|
| submit handler | `const o = rows[0];` 之后 | `const user = req.user || {};` |
| withdraw handler | `const o = rows[0];` 之后 | `const user = req.user || {};` |
| PUT/edit handler | `const orderId = req.params.id;` 之后 | `const user = req.user || {};` |

**改动量**：3 行，每处 1 行
**风险**：极低 — 与已正常工作的 4 个 handler 完全相同模式

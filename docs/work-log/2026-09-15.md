## 二、fix/165-175：月结付款 RelatedApproval 链路 11 连修

### 2.1 背景

供应商月结付款提交企微审批时连续报错，涉及多个层面：
1. 金额取错（用申购金额而非实际收货金额）
2. RelatedApproval 关联审批单接口字段反复试错（sp_no / template_id / sp_name 三字段）
3. 跨企微应用的 sp_no 导致提交失败
4. 错误响应不透明，难定位
5. Selector 控件 key 用中文文本导致企微拒绝
6. 发起人硬编码导致"操作人 A 但发起人 B"错乱
7. 备注控件 ID 与已有控件撞 ID
8. 驳回/撤销后采购单卡在审批中列表

### 2.2 修复链

#### fix/165 `c259db5` — 用 actual_amount 替代 total_amount

[reconciliation.js](file:///f:/OA/backend/routes/reconciliation.js)
- `/generate`、`/stats/overview`、`/monthly/pending-suppliers` 三处 SQL 把 `SUM(total_amount)` 改为 `SUM(CASE WHEN actual_amount > 0 THEN actual_amount ELSE total_amount END)` 或 `toNum(row.actual_amount) || toNum(row.total_amount)`
- 月结金额应优先用实际收货金额，没有时回退到申购金额

#### fix/166 `e4db15c` — getApprovalDetail info 路径

[reconciliation.js](file:///f:/OA/backend/routes/reconciliation.js)

#### fix/175 `a965745` — 驳回/撤销后恢复采购单到待月结列表 ⭐

- 前端 `handleRefreshPaymentStatus` 增加 `fetchPendingSuppliers()` 调用同步刷新待月结列表，并补充 `sp_status=4` 的 toast 提示

### 2.3 状态流转总结

| sp_status | 含义 | 采购单处理 |
|-----------|------|------------|
| 1 | 审批中 | 保持 `monthly_payment_sp_no`，留在审批中列表 |
| 2 | 已通过 | `monthly_paid_at = NOW()`，标记付款完成 |
| 3 | 已驳回 | `monthly_pending=1, monthly_payment_sp_no=NULL`，回到待月结 |
| 4 | 已撤销 | 同上 |

## 五、踩坑教训（同步到项目记忆）

1. 企微 RelatedApproval 跨企微应用 sp_no 会报错，必须提交前 `getApprovalDetail` 预验证跳过（fix/169）
2. 企微 Selector 控件 key 必须是 `option-xxx` 格式，不能用中文文本（fix/172/173）
3. try/catch 作用域：catch 块要访问的变量必须 `let` 在 try 外声明（fix/171）
4. contents 数组中控件 ID 必须唯一，自动发现未配置字段时需用 Set 跟踪 filledIds（fix/174）
5. 企微审批发起人必须用 `req.user.wecom_userid`，不能用 `config.applicant_userid`（fix/174）
6. 月结金额优先 `actual_amount`，无则回退 `total_amount`（fix/165）
7. 后端 catch 块应返回 `debug_info` 帮助前端定位问题控件（fix/170）
8. 月结付款 sp_status 状态流转：3/4 需恢复 `monthly_pending=1` 让采购单回到待月结列表（fix/175）

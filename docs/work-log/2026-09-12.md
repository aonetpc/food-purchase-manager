## 二、fix/147：循环依赖导致同步脚本崩溃

### 2.1 现象

部署后执行 `node scripts/sync_expense_approvals_full.js` 报错：

```
TypeError: Router.use() requires a middleware function but got an Object
```

### 2.2 根因

`routes/expense-approvals.js` 和 `routes/wecom.js` **互相 require**：
- `expense-approvals.js` 顶部 `require('./wecom')`
- `wecom.js` 顶部 `require('./expense-approvals')`

Node.js 循环依赖导致其中一个模块在加载时导出**空对象 `{}`**，`Router.use()` 收到的不是函数而是对象，崩溃。

### 2.3 修复

把 `expense-approvals.js` 里的 `require('./wecom')` 改为**懒加载函数**：

```js
// 旧：顶部 const wecom = require('./wecom');
// 新：
function getWecomHelpers() {
  return require('./wecom');
}
// 使用时：getWecomHelpers().someFunction()
```

`require` 只在第一次调用时执行，此时两个模块都已加载完成，避免循环依赖。

## 四、fix/149 + fix/150：迁移 114 未真正落地 amount 列

### 4.1 现象

部署后前端金额显示不对，查数据库发现 `wecom_expense_approvals` 表**没有 amount 列**，但 `schema_migrations` 表里迁移 114 已标记为 `completed`。

### 4.2 根因：migrate.js 按分号拆分 SQL 导致部分执行

迁移 114 用了 **PREPARE/EXECUTE 动态 SQL**（因为要判断列是否存在再加列）：

```sql
SET @col_exists = (SELECT COUNT(*) FROM information_schema.COLUMNS ...);
SET @sql = IF(@col_exists = 0, 'ALTER TABLE ... ADD COLUMN amount ...', 'SELECT 1');
PREPARE stmt FROM @sql;
EXECUTE stmt;
DEALLOCATE PREPARE stmt;
```

`migrate.js` 的拆分逻辑是**按 `;` 分割**，把 PREPARE/EXECUTE 拆成多条独立 SQL 执行，导致：
- `PREPARE stmt FROM @sql` 单独执行（此时 @sql 变量可能已丢）
- `EXECUTE stmt` 单独执行失败
- 但 migrate.js 把整个迁移标记为 `completed`

**结果**：迁移 114 标记已完成，但 amount 列实际未添加。后续迁移 115 也受影响。

### 4.3 fix/149：改用 IF NOT EXISTS 替代 PREPARE/EXECUTE

MySQL 8.0+ 支持 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`，不需要动态 SQL：

```sql
ALTER TABLE wecom_expense_approvals ADD COLUMN IF NOT EXISTS amount DECIMAL(10,2) DEFAULT 0;
ALTER TABLE wecom_expense_approval_nodes ADD UNIQUE KEY IF NOT EXISTS uk_approval_node (...);
```

但**迁移 114 已标记 completed**，migrate.js 不会重新执行，所以这个修复对已部署环境无效。

### 4.4 fix/150：补加迁移 115 真正落地 amount 列 + 节点唯一键

新增迁移 115（`115_expense_add_amount_column.sql`），用简单 `ALTER TABLE` 重新添加 amount 列和节点唯一键（**不用 IF NOT EXISTS**，靠 migrate.js 的幂等错误忽略处理）。因为是新迁移编号，migrate.js 会执行。

**配套脚本**：`scripts/backfill_expense_amount_and_nodes.js` 回填已有数据的 amount。

## 五-b、fix/152：迁移 114 去掉 IF NOT EXISTS 语法（MySQL 不支持）

### 现象

部署后 `amount` 列仍不存在，`node migrations/migrate.js up` 报错：

```
错误：You have an error in your SQL syntax; ... near 'IF NOT EXISTS amount DECIMAL(12,2) ...'
errno=1064
```

### 根因

**MySQL 8.0.46 不支持 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 语法**（这是 MariaDB 语法，非标准 MySQL）。

fix/149 把迁移 114 从 PREPARE/EXECUTE 改为 `IF NOT EXISTS`，结果：
- 114 用 `ADD COLUMN IF NOT EXISTS` → errno=1064 语法错误
- migrate.js `up()` 失败 `process.exit(1)` → 被 deploy.yml 的 `|| echo` 吞掉
- 114/115 全部"待执行" → `amount` 列从未添加

### 修复

去掉 `IF NOT EXISTS`，改回简单 `ALTER TABLE`，靠 migrate.js 的幂等错误忽略机制：
- errno 1060 `ER_DUP_FIELD_DATA` → 字段已存在，跳过
- errno 1061 `ER_DUP_KEYNAME` → 索引已存在，跳过
- errno 1091 `ER_CANT_DROP_FIELD_OR_KEY` → 索引不存在，跳过

## 六、踩坑 & 教训

### 6.1 循环依赖用懒加载函数解决

**教训**：两个路由文件互相 require 会导致循环依赖，其中一个导出空对象。解决方案：把 require 改成函数 `function getXxx() { return require('./xxx'); }`，使用时调用，延迟到运行时才加载。

### 6.2 migrate.js 按分号拆分 SQL 不支持动态 SQL

**教训**：迁移 SQL 中**禁止使用 PREPARE/EXECUTE 动态 SQL**。migrate.js 按 `;` 拆分，会把动态 SQL 拆成多条独立语句，导致部分执行失败但迁移仍标记 completed。

### 6.3 MySQL 8.0 不支持 ALTER TABLE ADD COLUMN IF NOT EXISTS

**教训**：`IF NOT EXISTS` 子句在 `ALTER TABLE ADD COLUMN/DROP INDEX/ADD INDEX` 上是 **MariaDB 语法**，MySQL 8.0 不支持（虽然 MySQL 8.0 在 `CREATE TABLE` 等地方支持 `IF NOT EXISTS`，但 `ALTER TABLE` 上不支持）。迁移 SQL 中**禁止使用 `ALTER TABLE ... IF NOT EXISTS`**，改用简单 `ALTER TABLE` + migrate.js 幂等错误忽略。

### 6.4 迁移失败需查 schema_migrations 表确认实际落地情况

**教训**：迁移标记 completed ≠ SQL 真正执行成功。出现字段缺失时，先查 `schema_migrations` 看迁移状态，再 `DESCRIBE table` 确认字段是否存在，最后查 migrate.js 的拆分逻辑是否破坏了 SQL。

### 6.5 deploy.yml 的 `|| echo` 会吞掉 migrate.js 的错误

**教训**：deploy.yml 中 `node migrations/migrate.js up 2>&1 || echo "..."` 会把 migrate.js 的 `process.exit(1)` 吞掉，导致部署显示绿勾但迁移实际失败。迁移失败不会阻断部署，需要在迁移后检查 `migrate.js status` 确认。

### 6.6 重复声明变量导致 SyntaxError 部署失败

**教训**：同一个作用域内 `const`/`let` 不能重复声明。合并代码时注意是否有同名变量重复声明。`node --check <file>` 可提前发现语法错误。

### 6.7 permissions.type 枚举值需与系统一致

**教训**：权限类型字段有枚举限制（`ENUM('menu','button','api')`，定义在 001_init_rbac_tables.sql），新增权限时 type 必须用系统支持的值，不能随意用 'action'。语义上"操作权限"用 'button'。

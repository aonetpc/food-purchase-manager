## 五、fix/157：迁移 116 roles 表 INSERT 字段名错误

### 5.1 问题

feat/155 部署后 cashier 角色未创建，服务器手动执行迁移 116 的 INSERT 语句报错：

```
ERROR 1054 (42S22) at line 1: Unknown column 'status' in 'field list'
```

### 5.2 根因

迁移 116 的 INSERT 语句使用了 `status` 字段：
```sql
INSERT IGNORE INTO roles (id, code, name, description, sort_order, status)
VALUES (UUID(), 'cashier', '出纳', '...', 15, 1);
```

但 `roles` 表（定义在 `001_init_rbac_tables.sql`）**没有 `status` 字段**，只有 `is_system TINYINT` 字段。

### 5.3 部分执行现象

迁移 116 包含两条 SQL：
1. `INSERT IGNORE INTO roles ...` — **失败**（Unknown column 'status'）
2. `ALTER TABLE wecom_expense_payments ADD COLUMN received_status ...` — **成功**

migrate.js 按 `;` 拆分 SQL 逐条执行，INSERT 失败但 ALTER TABLE 成功，整个迁移标记为 completed。

验证：在服务器执行 `DESCRIBE wecom_expense_payments` 确认 4 个 received 字段已落地，但 `SELECT * FROM roles WHERE code='cashier'` 返回空。

### 5.4 修复（1 file，3增3删）

`backend/migrations/116_expense_cashier_role_and_received.sql`：
- `status` 字段改为 `is_system`
- `VALUES` 中 `1` 改为 `0`（非系统内置角色）

```sql
-- 修复前
INSERT IGNORE INTO roles (id, code, name, description, sort_order, status)
VALUES (UUID(), 'cashier', '出纳', '...', 15, 1);

-- 修复后
INSERT IGNORE INTO roles (id, code, name, description, sort_order, is_system)
VALUES (UUID(), 'cashier', '出纳', '...', 15, 0);
```

### 5.5 补救操作

迁移 116 已标记 completed，migrate.js 不会重新执行，因此在服务器手动执行修正后的 INSERT 语句创建 cashier 角色：

```bash
mysql -u food_purchase -p food_purchase -e "INSERT IGNORE INTO roles (id, code, name, description, sort_order, is_system) VALUES (UUID(), 'cashier', '出纳', '可标记费用支付状态，其他财务人员只能查看', 15, 0); SELECT id, code, name FROM roles WHERE code='cashier';"
```

## 六、fix/158：GET /my 路由被 /:sp_no 抢匹配导致 404

### 6.1 问题

feat/155 部署后"我的报销"页面打开报错"加载失败 - 审批单不存在"，前端请求 `/api/wecom/expense-approvals/my?page=1&pageSize=20&month=2026-09` 返回 404。

### 6.2 排查过程

1. 初步怀疑 Nginx 代理配置或后端端口问题 — 但费用支付监控页（同路径前缀 `/api/wecom/expense-approvals`）正常工作，排除 Nginx/端口
2. 在服务器用 curl 测试 `/api/wecom/expense-approvals/my` 返回 401（未授权），证明路由存在
3. 最终定位根因：Express 路由注册顺序问题

### 6.3 根因

Express 按路由注册顺序匹配，参数路由 `GET /:sp_no`（原 Line 526）注册在静态路由 `GET /my`（原 Line 752）**之前**。

请求 `/my` 被 `/:sp_no` 抢先匹配，`sp_no` 被赋值为 `"my"`，数据库 `SELECT * FROM wecom_expense_approvals WHERE sp_no = 'my'` 查不到记录，返回 404 "审批单不存在"。

### 6.4 修复（1 file，92增89删）

`backend/routes/expense-approvals.js`：
- 把 `GET /my` 路由整段移动到 `GET /:sp_no` 路由之前注册
- 添加注释说明顺序要求防止回归

修复后路由顺序：
| Line | Method | Path | 说明 |
|------|--------|------|------|
| 436 | GET | `/` | 列表 |
| 531 | GET | `/my` | 我的报销（已移到前面） |
| 618 | GET | `/:sp_no` | 详情 |
| 656+ | POST | ... | 其他写操作 |

### 6.5 Nginx 端口排查结论

排查过程中曾怀疑过 Nginx 代理/端口 3001 配置，最终确认与端口无关：
- Nginx 配置 `proxy_pass http://localhost:3001` 一直正确
- 端口 3001 是后端标准配置，从未被改动
- 费用支付监控页正常工作本身就是端口正确的证明

## 七、踩坑 & 教训

### 7.1 Express 路由按注册顺序匹配，参数路由会抢先匹配静态路径

**教训**：Express 路由匹配是按注册顺序的，参数路由（如 `/:sp_no`）会匹配任何单段路径，包括 `/my`。静态路由（如 `/my`）必须注册在参数路由**之前**，否则永远匹配不到。

### 7.2 roles 表无 status 字段，INSERT 必须用 is_system

**教训**：`roles` 表（`001_init_rbac_tables.sql`）只有 `is_system TINYINT` 字段，没有 `status` 字段。INSERT 语句中需用 `is_system` 代替 `status`。这是数据库版本相关的约束：迁移 SQL 必须与实际表结构字段名一致。

### 7.3 migrate.js 部分执行成功：INSERT 失败但 ALTER TABLE 成功

**教训**：migrate.js 按 `;` 拆分 SQL 逐条执行，一条失败不影响其他条执行，整个迁移仍标记为 completed。这意味着迁移标记 completed ≠ 所有 SQL 都执行成功。排查时需要分别验证每条 SQL 的结果（如 `DESCRIBE table` 确认字段是否存在 + `SELECT` 确认数据是否插入）。

### 7.4 排查 404 时优先检查路由顺序而非 Nginx/端口

**教训**：当某个接口 404 而同前缀的其他接口正常时，首先检查 Express 路由注册顺序，特别是参数路由是否抢匹配了静态路径。不要过早怀疑 Nginx/端口（如果同前缀接口能用，Nginx/端口就是好的）。

## 一、fix/187：盘点 H5 实盘数输入框修复尾部零被吞问题

### 1.1 背景

用户在盘点 H5 页面录入"骨钙素检测试剂盒-安图"实盘数时，系统数量为 3.06，但输入框无法输入 3.06，只能输入 3 或 3.1。输入 3.16、3.26 都正常，唯独"几点零几"不能输入（如 3.06、3.05、3.01 等）。

### 1.2 根因

[StockTakeOperate/index.tsx](file:///f:/OA/src/pages/StockTakeOperate/index.tsx) 受控数字输入框的 value 用 `String(Number(v))` 转换：

```tsx
// 修改前
const inputValue = actual === null ? '' : String(actual);
onChange={(e) => {
  const v = e.target.value;
  updateItem(it.id, { actual_quantity: v === '' ? null : Number(v) });
}}
```

**"尾部零丢失"经典 bug**：

| 用户输入 | `e.target.value` | `Number(v)` | `String(Number(v))` = 重渲染显示值 |
|---------|-----------------|-------------|----------------------------------|
| "3" | "3" | 3 | "3" ✓ |
| "3." | "3." | 3 | "3" ❌ 丢掉 "." |
| "3.0" | "3.0" | 3 | "3" ❌ 丢掉 ".0" |
| "3.06" | "3.06" | 3.06 | "3.06" ✓（但前面已丢，光标错乱） |

而 "3.16" 不丢：`Number("3.1")` = 3.1 ≠ 3，`String(3.1)` = "3.1" 保住了。

**根因**：`Number("3.0") === 3`，`String(3) === "3"`，把输入框的 "3.0" 强制重渲染成 "3"，丢了 ".0"，导致用户无法继续在 ".0" 后面输入 "6"。

### 1.3 修复方案（commit `bdef482`，1 file，+29/-2）

引入独立的"草稿字符串"状态，专门保存用户正在输入的原始字符串，显示优先用草稿，失焦时才提交并清除草稿。

**新增状态** [StockTakeOperate/index.tsx#L247-L249](file:///f:/OA/src/pages/StockTakeOperate/index.tsx#L247)：
```tsx
const [draftActual, setDraftActual] = useState<Record<string, string>>({});
const [draftVerify, setDraftVerify] = useState<Record<string, string>>({});
```

**operator 实盘数输入框** [L823-L874](file:///f:/OA/src/pages/StockTakeOperate/index.tsx#L823)：
```tsx
// 显示值：有草稿用草稿，无草稿用 Number→String
const inputValue = draftActual[it.id] !== undefined
  ? draftActual[it.id]
  : (actual === null ? '' : String(actual));

// onChange：只更新草稿字符串（保留原始输入含尾部零）+ 同步解析给 diff 计算
onChange={(e) => {
  const v = e.target.value;
  setDraftActual(prev => ({ ...prev, [it.id]: v }));
  updateItem(it.id, { actual_quantity: v === '' ? null : Number(v) });
}}

// onBlur：失焦时提交最终解析值，清除草稿（回落到 String(actual)）
onBlur={() => {
  const raw = draftActual[it.id] ?? '';
  const parsed = raw === '' ? null : Number(raw);
  updateItem(it.id, { actual_quantity: parsed });
  setDraftActual(prev => { const n = { ...prev }; delete n[it.id]; return n; });
}}
```

**reviewer 核验数量输入框** [L976-L989](file:///f:/OA/src/pages/StockTakeOperate/index.tsx#L976)：同样的草稿字符串方案。

### 1.4 验证

- 继续输入 "6" → "3.06" 成功

## 二、踩坑教训

1. **受控数字输入框不能用 `String(Number(v))` 做 value**（ref：fix/187，2026-09-24）：`Number("3.0") === 3` 会吞掉尾部零，导致无法输入"几点零几"的小数。必须用草稿字符串保存原始输入，onChange 只更草稿，onBlur 才提交解析值。
2. **所有 `<input type="number">` 受控组件都要检查是否有同样问题**（ref：fix/187，2026-09-24）：盘点 operator 实盘数和 reviewer 核验数两处都有同样的 bug，修复时必须一起改。

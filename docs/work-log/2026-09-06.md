## 二、销售员列表为空 Bug 修复

### 2.1 现象

分享弹窗里销售员列表显示"暂无销售员数据"。

### 2.2 根因

用了**原生 fetch + 错误的 token key**：

```javascript
// 错误：token key 不对，认证失败
fetch('/api/booking/config', {
  headers: { 'Authorization': `Bearer ${localStorage.getItem('token') || ''}` }
})
```

项目实际的 token 管理在 `src/lib/api.ts` 的 `getToken()` 里（不是 `localStorage.getItem('token')`），导致请求返回 401，销售员列表为空。

### 2.3 修复

改用和 [PackagesTab.tsx](file:///f:/OA/src/pages/CheckupCenter/PackagesTab.tsx#L79-L84) 一样的方式——封装好的 `api.get('/booking/config')`，自动带正确的 token：

```javascript
import { api } from '@/lib/api';
const cfg = await api.get('/booking/config');
setSalesUsers(cfg?.data?.salesUsers || []);
```

## 五、新增约束（写入项目记忆）

1. **API 调用统一用封装好的 api 对象**：禁止用原生 fetch 调业务接口，必须用 `api.get/post/put/delete`（`@/lib/api`），token 管理统一在 `api.getToken()`
2. **amend 前双确认当前分支**：执行 `git commit --amend` 前必须 `git branch --show-current` 确认在目标分支，不在 main
3. **资源操作权限基于 owner 判断**：套餐分享/分配等"操作自己资源"的权限，应基于 `owner_sales_id === user.id` 判断，不是硬编码角色
4. **cover_sales_ids 不包含 owner 自己**：分享接口自动过滤 owner 的 user.id

# 体检套餐默认选中失效修复方案

## 问题诊断

### 现象
在体检预订下单页面选择套餐后，点击"配置项目"按钮打开的编辑弹窗中，原套餐项目没有显示为"默认选中"状态（绿色标签），所有201个项目库项目都显示为白色未选中状态。

### 根本原因
**`fromBackend` 函数递归转换导致数据键名不匹配。**

在 [api.ts:402](file:///workspace/src/lib/api.ts#L402) 的 `getConfig()` 函数中：

```tsx
packages: (res.data?.packages || []).map(fromBackend),
```

`fromBackend` 函数会递归将所有 snake_case 键名转为 camelCase，包括套餐内嵌套的 items 数组元素：
- `item_id` → `itemId`
- `item_name_snapshot` → `itemNameSnapshot`  
- `item_price` → `itemPrice`

但在 [Create.tsx](file:///workspace/src/pages/BookingBoard/Create.tsx) 中，渲染代码统一使用 snake_case 读取这些字段：
- `i.item_id` → 实际值为 `undefined`（因为键名已变为 `itemId`）
- `i.item_name_snapshot` → `undefined`
- `i.item_price` → `undefined`

这导致：
1. `defaultSelectedIds` Set 为空（因为 `item_id` 为 undefined，过滤后无有效ID）
2. `finalLib` 中的 fallback 项目也无法正确生成（同样因 `item_id` 为 undefined 被跳过）
3. 对话框中所有项目的 `isDefault` 判断始终为 `false`

注：同一函数内的 `checkupItems` 已有注释说明不走 `fromBackend`（第407行），但 packages 的 items 被遗漏了。

## 修复方案

### 修改文件
- `src/lib/api.ts` — `getConfig()` 函数

### 实施步骤

1. **修改 `getConfig()` 中 packages 的映射方式**：在 `fromBackend` 转换后，将嵌套的 `items` 数组元素的键名恢复为 snake_case，保持与渲染代码一致。

   具体做法：对 `fromBackend` 转换后的 packages 结果，遍历每个 package 的 items，将 `itemId` → `item_id`、`itemNameSnapshot` → `item_name_snapshot`、`itemPrice` → `item_price` 等 camelCase 键还原为 snake_case。

2. **无需修改 `Create.tsx`**：因为渲染代码已统一使用 snake_case，修复数据源后即可正常工作。

### 详细代码变更

```tsx
// getConfig() 中 packages 的映射修改为：
packages: (res.data?.packages || []).map((p: any) => {
  const transformed = fromBackend(p);
  // 修复：fromBackend 会将嵌套 items 的 snake_case 转为 camelCase，
  // 但 BookingBoard 渲染代码使用 snake_case 读取，需要还原
  if (transformed.items && Array.isArray(transformed.items)) {
    transformed.items = transformed.items.map((it: any) => ({
      item_id: it.itemId ?? it.item_id ?? '',
      item_name_snapshot: it.itemNameSnapshot ?? it.item_name_snapshot ?? '',
      item_price: it.itemPrice ?? it.item_price ?? 0,
      quantity: it.quantity ?? 1,
      remark: it.remark ?? '',
      sort_order: it.sortOrder ?? it.sort_order ?? 0,
    }));
  }
  return transformed;
}),
```

## 依赖与注意事项

- **top-level 字段不受影响**：`id`、`code`、`name`、`price`、`status` 等套餐顶层字段无下划线，转换前后不变。`sort_order`、`item_count`、`auto_total` 等字段会变为 camelCase，但 BookingBoard 页面未使用这些字段，不影响。
- **其他页面兼容性**：BizConfigModal 使用独立的 `listPackages()` 接口，也经过 `fromBackend`，但它使用独立的 items 查询接口获取项目列表，不受此影响。
- **正向兼容性**：`itemId` 优先于 `item_id`，确保即使后端返回的字段名有变化也能正确处理。

## 验证方案

1. 打开体检预订下单页面
2. 选择一个套餐
3. 点击"配置项目"按钮
4. 验证：弹窗中原套餐的项目显示为绿色"套餐"标签，标记为"原套餐保留"
5. 验证：弹窗底部统计数据中"原套餐保留"数量 > 0
6. 测试增减操作：移除/恢复原套餐项目、追加新项目

## 风险评估

- **风险**：低。修改仅限于 `getConfig()` 中 packages 数据的嵌套 items 键名还原，不影响其他模块。
- **回退方案**：如出现异常，可移除 items 还原逻辑，恢复原始 `fromBackend` 映射。
